# سيناريو عرض من عشرين دقيقة
نفّذ الأوامر في PowerShell من جذر المجلد المجهّز. على جهاز Docker استبدل ‎.\local.ps1 بـ docker compose run --rm app. اقرأ النتائج على الشاشة مع الجمهور.

**الدقائق 0–5، رحلة الزائر.** ابدأ بسؤال «أي جولة تناسب زائرًا مهتمًا بعمارة الخليل؟». اعرض دورة الحالة وسبب وجود قيد فريد على حدث الزيارة. اشرح لماذا يجب إكمال الحجز قبل المراجعة.
```powershell
$site=.\local.ps1 id site 1 | ConvertFrom-Json
$visitor=.\local.ps1 id visitor 1 | ConvertFrom-Json
$tour=.\local.ps1 id tour 1 | ConvertFrom-Json
.\local.ps1 analytics
```
على العينة الأصلية: 3 زيارات للبلدة القديمة، ومتوسط 4.00. في مارس زيارتان بمتوسط 4.50 ومهلة 3 أيام. في أبريل زيارة واحدة للموقع بمهلة 5 أيام. الخميس أكثر أيام العينة زيارة (3)، والربعان الأول والثاني متساويان (زيارتان لكل منهما).

**الدقائق 5–10، أين تقيم البيانات؟** اتبع سهام المعمارية. افتح ملف موقع ووثيقة جولة. ابحث عن عمارة الخليل بالعربية وفسّر ترتيب النتيجة.
```powershell
$city=.\local.ps1 id city 1 | ConvertFrom-Json
.\local.ps1 search $city عمارة ar
.\local.ps1 listing $site
```
نتيجة البحث: البلدة القديمة في الخليل بجولتين ثم حارة العقابة دون جولات.

**الدقائق 10–15، الرسم.** في Neo4j Browser اعرض الرسم بأمر ‎`MATCH p=(g:Guide)-[:COVERS]->(s:Site)-[:NEAR]-(n:Site) RETURN p LIMIT 25`. عرّف المتغير ‎`:param id => '00000000-0000-0000-0000-0000001e8481'` وشغّل محتوى db/neo4j/coverage.cypher. يغطي سليم ثلاثة مواقع من مجموعة الأصل والقريبين وتغطي ريم موقعين. شغّل التوصية لنور. تزور رنا الموقع نفسه وتشاركها اهتمام العمارة، وتضيف زيارة رنا لسوق القزازين سببًا لتوصيته لنور.
```powershell
.\local.ps1 recommend $visitor
```

**الدقائق 15–20، العرض المتكامل.** شغّل seed لإبطال الصفحات، واقرأ نفس الموقع مرتين. قارن miss ثم hit. اطلب جولة وأضف تقييمًا جديدًا وتحقق من الزيارات والذاكرة. راجع مخاطر تأخر الإسقاط وحدود بيانات العينة.
```powershell
.\local.ps1 seed
.\local.ps1 site $site
.\local.ps1 site $site
.\local.ps1 cache-info $site
$b=.\local.ps1 request-booking $visitor tours $tour | ConvertFrom-Json
.\local.ps1 confirm-booking $b
.\local.ps1 complete-booking $b
.\local.ps1 add-review $b 5 "أعجبني شرح العمارة"
.\local.ps1 site $site
.\local.ps1 audit
```
الزيارة الجديدة ترفع العدد من 3 إلى 4 ومتوسط التقييم من 4.00 إلى 4.25 إذا بدأ العرض من العينة الأصلية. تُظهر الاستجابة الأخيرة miss. إذا ظهرت projection=pending، شغّل sync ثم audit بعد عودة Neo4j.

**أسئلة للمناقشة.** لماذا لا نحسب الزيارات من عدد علاقات VISITED؟ لأن عدة زيارات لنفس الزائر والموقع تختصر في علاقة واحدة. لماذا يُقبل تأخر الرسم؟ لأن قرار أهلية المراجعة يُقرأ من سجل الحجز الدائم. ماذا يحصل للطلب البارد إذا توقفت MongoDB؟ يفشل الطلب بالكامل. كيف تميّز مصالح زائرين لهما نفس اللغة؟ التوصية تتطلب تقاطع الاهتمامات، واللغة تستخدم في البحث المنفصل.
